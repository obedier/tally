- **D-048 (2026-07-29)** — Cost tracking for unit economics (owner: "make sure we're tracking gemini and kimi spending… project cost forward… help define the business model"). Kimi's audit adds $0.0036 (2.1%). So unit cost is driven by evidence-batch COUNT, not by model choice or prompt length: dropping full mode from 3 batches to 2 saves ~21% of total cost, while halving every prompt would save ~5%. `groundedRequests` is therefore tracked as a first-class quantity rather than folded into token math. - **D-049 (2026-07-29)** — Research provider made configurable; Kimi-primary trialled and reverted (owner: "use Kimi for all primary research and gemini 2.6 as a second opinion… make it configurable so we can easily switch back if needed or quality is bad. - **D-050 (2026-07-29)** — **Kimi works as the sole research engine.** D-049 reverted the Kimi trial on the conclusion that it "cannot cite" and "times out". Both diagnoses were wrong; four distinct bugs were hiding behind them, each found by measuring rather than reasoning. (1) **Truncation, not disobedience.** The grounded call hit `finish_reason: "length"` at `max_tokens: 8000` — ~6300 tokens went to invisible reasoning (k2.6 returns it in a separate `reasoning_content` field) leaving 1709 characters of content that stopped mid-CANDIDATES. Because the evidence prompt puts `SOURCES:` last, truncation removed exactly the citations. Worse, truncated text was being *accepted* as valid evidence; only the zero-source guard caught it. `finish_reason: "length"` is now a hard error (`code: "truncated"`) on both call paths, and grounded headroom is 16k. (2) **A dropped `type: "builtin_function"`.** Echoing the tool call back without it means Moonshot never runs the server-side search; the model then tries to search by printing `<function_calls>` blocks as prose and returns a fluent, sourceless, evidence-free answer — a silent failure that reads exactly like "cannot cite". (3) **undici's `headersTimeout`, not Moonshot.** Non-streaming completions send no headers until generation finishes, so minute-long calls died inside Node's fetch as an unattributable `TypeError: fetch failed` (UND_ERR_HEADERS_TIMEOUT) that our AbortController never saw — previously misread as "the connection dropped from too much reasoning". All Kimi calls now **stream**, purely so headers arrive immediately and the AbortController is the single honest owner of the time budget. (4) **The loop never terminated.** Withdrawing the tools does not stop the model searching — it just writes the calls as text — so the final hop now carries an explicit instruction to answer from what it has, and the hop cap fell 3 → 2. Also settled: **reasoning effort selects between two different machines and is coupled to temperature by the API** (reasoning modes accept only `temperature: 1`, `"none"` only `0.6`). Grounded search REQUIRES reasoning (without it the agentic loop dies after one hop); synthesis REQUIRES `"none"` (at `"low"` it reliably died, and non-reasoning cut synthesis from ~130s to 41s). Provider selection is now genuinely whole-pipeline: `fastJson` was added because classify and evidence-structuring were still hardcoded to Gemini, so `RESEARCH_PROVIDER=kimi` had never actually been a single-model configuration. The Gemini-key guard at pipeline entry was removed for the same reason — it made Kimi-only impossible to run. **Verified live, Gemini fallback disabled:** a quick research returned HTTP 200 with a complete report, 5 sources, every one a DIRECT publisher URL (cnet.com, rtings.com, recordingnow.com) instead of Gemini's `vertexaisearch` redirect wrappers, prices and a 4.2/5 rating attributed to CNET, an honest "multipoint support unconfirmed in evidence" con, and confidence capped at medium citing thin coverage. **Gemini stays the default for latency alone:** that run took 442s (classify 7.6s, evidence 393.6s = 89%, synthesis 41.1s) versus seconds for Gemini. The bottleneck is one grounded call generating ~10.8k output tokens at Moonshot's ~30 tok/s — an output-length problem, not a model-choice one. Config is `RESEARCH_PROVIDER=kimi` plus optional `RESEARCH_FALLBACK=false`; `KIMI_DEBUG=1` logs per-hop timing and dumps the tail of any sourceless answer. 304 tests green.

- **D-051 (2026-07-29)** — **Default Kimi model → `kimi-k2.7-code-highspeed`**, and the reasoning contract is now learned per model instead of hardcoded. Prompted by "maybe we should use a newer model like K3", tested rather than assumed. **k3 is unusable for research:** it emits a `$web_search` tool call and then rejects that identical call echoed back — "Invalid request: tokenization failed" — verified against five echo shapes (verbatim server message, empty content, no content key, tool message without `name`, no tools on the echo hop), streaming and non-streaming. It is a k3-side limitation of the builtin-search protocol, not our bug; k3 handles ungrounded JSON fine, which is not where the time goes. **k2.7-code-highspeed is dramatically faster:** the same real evidence prompt returned in **30.6s vs k2.6's 393.6s (12.9x)** with the same four sections and comparable citations, taking an end-to-end quick research from **442s → 74s** (classify 6.1s, evidence 38.4s, synthesis 28.2s). It also eliminated k2.6's mid-answer drift into Chinese (0 CJK characters). The "code" in the name is misleading for this workload. **Per-model reasoning rules:** k2.6/k3 accept `reasoning_effort: "none"` (temperature 0.6); the k2.7 family is reasoning-only and answers "invalid thinking: only type=enabled is allowed for this model" (temperature 1). Hardcoding a model list would go stale every Moonshot release, so the client now reads the constraint off the 400, downgrades to `"low"`, retries, and **remembers it per model** so later calls skip the failed round trip — a new retryable `reasoning-required` code, unit-tested. **The open concern is source quality, not speed.** Two live Kimi-only runs returned 3 and 7 sources against Gemini's 22 on a comparable query, and the vacuum query's citations included `texasdiamondgarage.com`, `qwertycompare.com`, `thirstybear.com` and `theconsumers.guide` — SEO content farms rather than authoritative reviewers, where Gemini surfaced rtings/CNET-class sources. Kimi's URLs are *direct* (their advantage) but currently *thinner and lower-authority* (their cost). Since trust outranks speed in the CLAUDE.md priority order, this — not latency — is now what keeps Gemini the default. Tracked as TODOS item 12. 308 tests green.
