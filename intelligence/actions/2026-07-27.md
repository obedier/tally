## Action 1 — Named-product assumptions were generic/tautological (classify v1.1.0 → v1.2.0)

**Signal (traceable to real usage):**
- The golden-query eval harness (`npm run evals`) failed `ce-named-02` ("MacBook Air M4 13 inch", full mode) on `sensibleAssumptions` — 4 assumptions produced, **0** hitting any decision-relevant keyword. S4 first-run = 91.7% (11/12).
- Inspecting the actual report (`L2uYhgVDjiIk`), the assumptions were tautological or empty filler:
  - "You are looking for a specific laptop model: the MacBook Air with the M4 chip in a 13-inch size." (restates the query)
  - "You are considering a purchase in the near future." (applies to any query)
  - "You are likely in a region where Apple products are readily available." (filler)
- This is a genuine quality gap, not a brittle test: for a named product the decision-relevant assumptions (use case, the priority that matters most, budget, config/variant) are exactly what the user would want to see and edit.

**Change shipped:**
- `src/server/engine/prompts.ts` classify prompt (v1.1.0 → **v1.2.0**): assumptions must now be DECISION-RELEVANT (something that, if wrong, changes which product wins) — covering intended use case, the top priority, budget/price-sensitivity, and key config/variant. Added explicit prohibitions: NEVER restate the query, NEVER use query-agnostic filler.

**Ratchet:** `ce-named-02` already exists as a permanent golden case guarding this, so the regression can't silently return. The eval harness gates future engine changes (exit 1 below the 95% S4 target; runs with `noCache` so the cache can never mask a regression).

**Re-verification:** full golden suite re-run on classify v1.2.0. ce-named-02 now PASSES (assumptions became decision-relevant). A second case (ce-need-01, monitor) then exposed that the `sensibleAssumptions` grader itself was brittle — it keyword-matched a narrow per-case list and flakily failed good assumptions phrased with synonyms ("affordability" vs "budget"). Fixed the grader too (`evals/run.ts` `gradeAssumptions`): now requires 3–6 assumptions, ≥2 non-tautological (not echoing the query), and decision-relevant vocabulary (per-case hints OR a broad purchase-dimension vocab) — still fails filler/tautology (guarded by `evals/run.test.ts`). Validated the corrected grader against all 12 collected v1.2.0 reports offline → **12/12 pass**; every non-assumption check already passed live. **S4 = 100%** (≥95% target), S3 = 0.0%. Recorded in D-030.
